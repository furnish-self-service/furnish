Furnish 0.2.0 adds current-user installations, release-channel selection and new tools for collection authors.

### Installing and updating Furnish

- **Windows x64:** Run `furnish_0.2.0_windows-x86_64_user-setup.exe` for your account. It includes the desktop, CLI, Git, Git LFS and DSC resources. Install a newer current-user setup to update. The MSI remains the all-users installer.
- **macOS on Apple silicon:** Open the disk image and drag Furnish into `~/Applications` for your account. The downloaded app verifies and installs its own updates. It includes Git LFS and uses the system Git.
- **Linux x86-64:** Extract `furnish_0.2.0_linux-x86_64_user.tar.gz` into a directory you own and run `furnish/bin/furnish-gui` or `furnish/bin/furnish`. Furnish verifies signed updates and replaces the extracted installation without administrator rights. Users of earlier archives can install this release manually once to enable updates. The desktop needs GTK 3, WebKitGTK 4.1 and Ayatana AppIndicator. Collections need Git and Git LFS.
- **Packagers:** Each platform has a separate binary-only archive. Verify it against this release’s `SHA256SUMS`.
- **Update channels:** Settings → About shows Stable or Alpha. The Windows MSI, downloaded macOS app and Linux current-user archive can switch channels there, keeping your update preferences. Other installations show how to switch through their package source.

A current-user installation runs with your account’s permissions. System-wide catalog steps still require administrator approval or an IT-managed Furnish service. Windows uses an unsigned installer and macOS uses ad-hoc signing without notarization. Organization policies still apply.

### Catalog changes

- App and kit descriptions support themed Markdown with embedded images.
- Uninstall previews identify the package manager and package and flag older installs whose original manager was never recorded.
- Kits skip unavailable members during CLI preview and install. Installed counters reflect applicable members. Collection authors can assert applicable, required and preselected members with `expectKits` in target profiles.
- Zero Install is a `Furnish/Package` installation method. If you used the experimental `Furnish/ZeroInstall` resource in alpha, migrate the step to `Furnish/Package` with `packageManager: 0install`, the launcher `name` and the `feed` URL.
